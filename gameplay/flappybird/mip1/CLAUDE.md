3. Map each panel uniformly onto **1080 x 1920** (substitute dimensions only when explicitly approved):

   ```text
   scale = min(panelWidth / 1080, panelHeight / 1920)
   offsetX = panelX + (panelWidth - 1080 * scale) / 2
   offsetY = panelY + (panelHeight - 1920 * scale) / 2
   canvasX = (referenceX - offsetX) / scale
   canvasY = (referenceY - offsetY) / scale
   canvasWidth = referenceWidth / scale
   canvasHeight = referenceHeight / scale
   ```

   Never copy reduced-preview pixels directly or scale axes independently. Preserve `useScaleUI`/viewport-background exceptions.

### Preparation and public API

- Import short effects with `?inline` so development and production use the existing Base64 asset pipeline. No runtime fetch, manual conversion, or decoding in input handlers. Invalid/missing assets or unavailable APIs must not freeze gameplay.
- Prepare `useSound(src, { backend, poolSize, desktopPoolSize, overflow, channel })` before relevant interactions. `backend: "media"` is the compatibility DEFAULT; choose `"web"` explicitly for buffered SFX. Do not infer backend from the gameplay name or user agent. No `lowLatency` option is implemented here; inspect/adapt callers when porting another project.
- `createSoundPool(src, options)` supports non-React owners, which MUST call `.dispose()`. React cleanup disposes on unmount/source/options changes; keep `channel` identities stable. `pool.ready` resolves true/false and `pool.error` reports preparation errors. For web, readiness includes decoding; for media, it confirms player construction, not audible playback permission or complete media loading. Check actual playback results too. Do not block input awaiting readiness.
- Shared limit: 32 allocated media players plus Web Audio voice slots. Web Audio also bounds cached assets at 32 and retained decoded buffers at 32 MiB, evicting unused settled entries as needed. Use small explicit voice counts; `desktopPoolSize` defaults to `poolSize`. Mobile detection includes touch-capable MacIntel iPadOS, not all touchscreen computers.
- Web: one shared interactive-latency context, cached concurrent decode promises/buffers, reusable gain slots, fresh single-use source nodes per cue. Media: bounded reusable players prepared once per owner and primed on eligible native gestures; no automatic switch when a play fails. A priming attempt is not proof that audible playback is allowed.
- `playSound(poolRef, { volume = 1, loop = false, pendingMs, replace = false, gesture = null })` is synchronous. It returns a playback handle or null; callers must tolerate null. Handle states: `pending`, `playing`, `ended`, `cancelled`, `failed`. Use `stopSound(handle)` / `.stop()`, `.muted`, `.paused`, `.duration`, `.currentTime`, `.ended`, `.finished`, and `ended`/`error`/`cancelled` events. Finished resolves status/reason/error; ONLY natural completion emits `ended`. Handles are not raw HTMLAudioElements: no `.play()`, `.pause()`, or assigning `.currentTime`. Inspect/adapt old callers that relied on those methods.
- One cue owner per action/state. `overflow: "replace-oldest"` replaces an occupied voice only when needed; `"drop-new"` protects active cues. Preserve intentional overlap. Optional `channel` groups pending/replacement ownership within the selected backend; do not use a channel to coordinate different backends. `replace: true` cancels active cues on that channel; newer requests supersede pending feedback, never queue a backlog.
- Web tap requests default to 250ms pending expiry; explicit `pendingMs` clamps to 0-2000ms. A loop with no explicit expiry remains owned until activation/cancellation; callers MUST cancel it on exit. Media retries use the same player with a 250ms throttle; optional `pendingMs` expires pending short feedback. Non-loop media has a 4s no-progress fallback by default. Preserve an owned scratch loop across idle mute/unmute; do not give it an arbitrary short tap expiry or rewind it during movement/retry.
